GPU 加速与 CPU 线程设置（2026-10-14）

使用方法
1. 本机已在项目 .gpu-runtime 目录安装 onnxruntime-directml 1.24.4，原 .venv 中的 CPU 运行库保留。
   其他电脑先安装 requirements.txt，再运行根目录“安装GPU支持.bat”。.gpu-runtime 不随 Git 同步。
2. 当前分析结束后关闭软件，通过原“启动测试工具.bat”重新打开本目录源码。
3. 在“资源占用（整机）”区域勾选“GPU 加速（自动分析 OCR）”，显卡选择 NVIDIA GeForce MX450。
   默认优先选择独立显存较多的显卡；可手动选择核显。列表编号使用 DXGI 顺序，不按 nvidia-smi 编号猜测。
4. 开始分析后查看“OCR：GPU / CPU”状态。初始化失败或执行中显卡出错会显示原因，
   自动用保留的 CPU 会话重算当前图片，不沿用上一帧的时间、容量。
5. CPU 高速模式默认仍用约 85% 的逻辑线程；“识别计算线程数”现在允许手动选择全部 8 个线程。
   手动设置优先于自动预算，分析期间不能切换。线程数是并行上限，不是整机 CPU 占用保证。

加速范围
- GPU 执行自动分析的 OCR 检测、方向分类与文字识别，包括时间、容量及普通 LCD 电量识别。
- 数码管样本匹配、受限形变校正、连续画面对比、关键帧回查及视频解码继续使用既有 CPU 路径。
- 手动补采和“测试当前帧”目前继续使用 CPU；GPU 开关标题已限定为自动分析。
- 不修改 OCR 模型、图像预处理、匹配门槛、抽帧间隔、时间算法和容量单位。
- DirectML 会话按官方要求禁用 memory pattern，并使用 ORT_SEQUENTIAL；每个引擎使用互斥锁保护调用。
  不支持的算子仍可能在 CPU 上执行。GPU 初次运行有图编译开销，短任务可能更慢。
- MX450 只有 2GB 显存；显卡占用不会持续为 100%，CPU 仍负责其余流程。
- 此更新仅为源码功能，旧 EXE 没有重新打包。现有分析进程不热更新，也不自动重启。

  静默退回 CPU、运行失败重读同一图片、缺少显卡/运行库及默认 CPU 路径。
- 界面设置保存、重新打开及分析期间锁定已覆盖，测试配置使用临时 INI，不写入用户设置。
- 完整双机 worker 的 0–200 秒对比已完成：同视频、同样本库、1 秒采样、2 验证线程、均启用回查。
